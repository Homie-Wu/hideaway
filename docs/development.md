# 开发与资源说明

地图的唯一数据源是 `src/world/layout.json`。房间、门洞、家具、支撑面、摆件槽位、通行路线和出生点共同使用这份数据。不要在截图或说明里另存一份可执行地图。

## 体素场景

- `design-architecture.ts` 生成建筑、楼板、屋顶与门窗。
- `voxel-furniture.ts` 和 `voxel-props.ts` 生成整数体素占用。可见网格与 Rapier 碰撞都由同一份占用数据得到。
- `prop-placement.ts` 检查实际支撑、实体交叉和槽位范围。固定家具不随机挪动，随机变化只使用经过检查的小物件槽位。
- `navigation.ts` 根据真实碰撞生成通行节点，并按角色体积过滤路径。床下等小藏点另行声明入口与净空。

房间应围绕生活用途安排家具和物件，保留门前、柜门前及主要路线的完整净宽。桌面丰富度来自有用途的少量组合；地面、墙面、灯具和家具结构共同承担视觉层次。

可模仿物件的模型范围不超过 32³。朝向通过旋转体素占用处理，环境和编辑器里的模型保持相同尺寸、轮廓和颜色。

## 猎人与武器

游戏仅加载 `public/models/characters/hunter-kit.glb`。其制作源在 `assets/characters/`；运行游戏不需要 Blender。资源 URL 使用 Vite 的基础路径，支持 GitHub Pages 子目录部署。

准备室的武器架与靶场提供实际射线交互。准备期练靶不影响正式伤害和积分，正式猎杀继续使用回合规则。

## 验证

`npm test` 检查模型保存、实体碰撞、门口净空、摆件支撑、导航、回合、编辑器与战斗行为。包含真实 Rapier 控制器的移动测试；浏览器编辑器测试在检测到兼容浏览器时执行。

`node tools/audit-map.mjs` 检查当前完整场景的家具、摆件与操作净空。`node tools/production-smoke.mjs` 打开生产构建，检查根路径和仓库子路径下的启动、角色资源、编辑器与存档操作。后者需要先执行 `npm run build`，并安装 Chrome / Edge，或设置 `CHROME_PATH`。

开发时可使用 `?map-review=房间ID` 检查布局，剖切相机只用于检查；正常游戏保持房顶与碰撞。生产构建不暴露检查入口及 `window.__game`。

临时截图和结果统一写入 `.artifacts/`，不提交到 Git。修改地图后重新运行相关检查，避免依赖旧截图或旧测试数量作为验收依据。
